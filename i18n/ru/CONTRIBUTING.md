Спасибо за помощь. Несколько правил помогают сохранять код tarjim понятным, а изменения в нём —
безопасными.

## Перед тем как открыть pull request

```bash
pip install -e ".[dub,dev]"
pytest
ruff check tarjim tests
mypy tarjim
```

Все четыре проверки должны пройти. Ограничения задаются конфигурацией в `pyproject.toml`: файлы
короче 200 строк, функции — меньше 20 операторов при сложности не выше 6, не более 4 аргументов,
строки короче 100 символов, `mypy --strict`.

## Как здесь вносятся изменения

- Сначала напишите падающий тест, затем код, с которым он проходит.
- Сначала измерьте, потом утверждайте: изменения тайминга, качества и скорости сопровождаются
  цифрами, которые их подтверждают, и записываются датированной строкой в `docs/decisions.md`
  (только дописывание).
- Смысл несут имена; комментарии объясняют лишь то, чего не может выразить сам код.
- Тексты интерфейса хранятся в языковых файлах (`tarjim/web/i18n`, `tarjim/extension/_locales`), на
  простом саудовском арабском и на английском. Никаких эмодзи в интерфейсе.
- Ничто не должно отправлять медиафайлы или ключи человека туда, куда он сам не выбрал. Локальный
  режим должен оставаться на нуле внешних соединений.
